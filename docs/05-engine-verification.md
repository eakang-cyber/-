# 05. 사주 계산 엔진 · 검증 계획

## 1. 구조

```
BirthInput ──► 음력→양력(lunar-javascript) ──► 현지 시각→UTC(Intl tzdata: 서머타임·UTC+8:30 시기 반영)
            ──► 절기 순간 비교(연주·월주)            ── lunar-javascript 절기(UTC+8 → UTC 변환)
            ──► 시간 기준 벽시계(clock | lmt | apparent) ──► 일주(JDN 공식) · 시주(자시 정책)
            ──► 십성·지장간·합충형 ──► 대운(방향·기산) ──► ChartResult(+warnings, verification)
```

- 코드: `src/engine/` · AI 언어모델은 계산에 관여하지 않음.
- 계산 정책(사용자가 `계산 기준` 화면에서 변경 가능):
  - **시간 기준**: `clock` 표준시 그대로 / `lmt` 경도 보정 평균태양시(기본, 서울 약 −32분) / `apparent` 진태양시(경도 + 균시차).
  - **자시 정책**: `zi23` 23시에 일주 변경(기본) / `midnight` 0시 변경, 23시대는 야자시(시간(時干)은 다음 날 일간 기준).
  - **절기**: 연주는 입춘 순간, 월주는 12절(節) 순간 기준. 시간 기준 정책과 무관(절대 시각 비교).
  - **대운**: 양남·음녀 순행, 음남·양녀 역행. 다음(이전) 절까지 일수 ÷ 3 = 년, 회귀년(365.2422일)로 날짜 환산.
- 출생시간 미상: 시주 미산출, 일주는 출생일 그대로, 대운 기산은 정오 근사.
- 성별 미선택: 대운 방향 미정(순행 임시 표시 + 안내).

## 4. Phase 2 외부 대조 계획 (통과 전까지 화면에 '미검증' 유지)

1. **기준 자료 확보**: KASI 음양력·24절기 자료(1901~2050), 상용 만세력 2종 이상(라이선스 확인 후 대조 목적만).
2. **경계 사례 300건 생성**: 입춘±10분, 각 절 ±10분, 23:00·00:00 ±5분, 시 경계(홀수 시) ±5분, 서머타임 시작·종료 시각, 1954·1961 표준시 변경일, 윤달 전후, 음력 말일(29/30일).
3. **자동 비교 리포트**: 원국 8자·대운 방향·대운 시작(일 단위) 불일치를 CSV로 출력. 불일치는 (a) 엔진 결함 (b) 정책 차이로 분류하고, (b)는 `계산 기준` 화면의 선택지로 노출.
4. **알려진 정책 차이**: 대운 시작 환산 방식 — 운명OS는 회귀년 환산, lunar-javascript는 1일=4개월·1시진=10일 관행. 기준 사례에선 같은 날짜가 나오지만 다른 사례에선 며칠 차이가 날 수 있다. 명리 검수자가 표준을 정한다.
5. **명리 검수**: 지장간 표(학파별 차이), 합화 성립 조건, 대운 기산 반올림 방식 — 검수자 2인 독립 검토 후 `review_status = approved`.
6. **회귀 방지**: 대조 통과 사례를 고정 테스트로 편입, `engine_version` 올릴 때마다 전체 재실행.

## 5. 해석 엔진 검증

- 규칙 레코드 필드: `rule_id, rule_name, source_title, source_location, school, conditions, interpretation, alternative_interpretations, conflicts, review_status, confidence_in_source, last_reviewed_at, version`.
- **출처를 지어내지 않는다**: 현재 15개 규칙 모두 `source_location = null`(원문 대조 전), `review_status = draft`. 고전 이름은 "어떤 관점(학파)에 기대는가"만 표시.
- 고전별 접근 차이 기록: 자평진전(월령 중심 격국), 적천수(일간 강약·통변), 궁통보감(계절·조후), 연해자평(십성 통변의 기본틀), 삼명통회(신살·형충회합 집성). 서로 섞지 않고 규칙마다 하나의 관점을 명시.
- 현대 번역본 인용 시 저작권 확인 후 원문(공유저작물) 위주로 인용.
- **WORK-ROLE-001**처럼 전통 규칙이 아닌 편집 해설은 `school: 현대 응용(전통 규칙 아님)`으로 구분.
